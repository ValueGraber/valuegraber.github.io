# ValueGrab: developer notes (read this instead of the whole template)

Site: https://valuegraber.github.io (GitHub Pages, `/docs` on `main`). Repo: ValueGraber/valuegraber.github.io.
Owner: Mon (Thai). All UI text is Thai, plain and calm.

## Files
- `src/template.html`: the source of truth for the page (~300 KB, one file: CSS, HTML, scripts). Do not read it whole; `grep -n` for anchors below.
- `src/calcs.js`: VI scoring (`CALC.scan/market/sectors`), inlined at `/*CALCS*/`.
- `tools/build.py`: builds `docs/index.html`. Always edit `src/`, then build. Never hand-edit `docs/index.html`.
- `tools/smoke.js`: opens every tab and sub-page on desktop and mobile with mock Firebase, fails on JS errors or overflow. Setup: `cd tools && npm i d3@7.9.0`.
- `tools/mockfb/`: fake Firebase (auth + Firestore in localStorage) for tests.
- `scanner.py` + `.github/workflows/update.yml`: daily cron (05:30 Thai, Tue–Sat) writes `docs/data.json` (500 S&P stocks, SPY, ^TNX, usdthb, eurthb, sekthb (`fx_thb`), gold GC=F, crypto BTC ETH SOL BNB XRP), `docs/history.json` (2y weekly closes incl. crypto) and `docs/prev.json` (previous day, for "what changed today").
- Non-S&P stocks: `EXTRA` in `scanner.py` (e.g. ANT, Anthropic IPO 2026-11-19) are appended to the universe; bars < 30 → price only, MAs/RSI null until enough history. `options_scan.py --all` picks them up from data.json (needs ≥ 2 bars).
- Schedule: every 30 min at :07/:37 from 05:07 to 10:07 Thai (Tue–Sat). Plus Monday night every 30 min 20:30–22:30 Thai (`30 13 * * 1`, `0,30 14-15 * * 1` UTC; crons ending in ` 1` pass `--live`) runs `fresh.py --live`: one intraday snapshot while NYSE is open; scanner writes `live: true` (asOf = today NY, before 16:30 NY), the web stamp says ราคาระหว่างวัน, and Tuesday morning still fetches the close because fresh.py never skips on `live`. Each scheduled run first runs `tools/fresh.py` (expected last NYSE close vs `docs/data.json` asOf, holiday list 2026–2027 inside) and skips in seconds when fresh; manual dispatch always runs. Update `HOLIDAYS` each year. Dispatch the workflow: `gh api -X POST repos/ValueGraber/valuegraber.github.io/actions/workflows/update.yml/dispatches -f ref=main`.

## Conventions
- Events: `vg:ready` (data.json loaded), `vg:data` (any user data changed → home + scan re-render), `vg:view` (tab shown), `vg:watch`, `vg:prefs`, `vg:add` (open portfolio form with a symbol), `vg:open` (stock sheet).
- Navigation: `window.VGNav.go(view, sub)` still takes old pairs like ('money','goals') or ('port','check'); `resolve()` maps them to tab/page and opens the group. Hashes: #money #invest #biz (old #portfolio #scan #business still work). Views: home, money, scan, port, biz.
- Storage keys: `valuegrab-portfolio-v1`, `valuegrab-biz-v1`, `valuegrab-money-v1`, `valuegrab-prefs-v1`, `valuegrab-watch-v1`.
- Firestore rules (already published by Mon): `match /{col}/{uid}`, owner only, `col in ['portfolios','business','money']`. A new top-level collection needs a rule change.
- Expense categories: housing + water/electricity = `ที่พักและค่าน้ำไฟ`, internet/phone = `ค่าเน็ตและโทรศัพท์`; old names are mapped in `norm` (`mapCat`).
- Sync: `push` remembers what it sent (`s.last`, key-sorted JSON); the snapshot that echoes our own write is skipped, so typing is never interrupted by a redraw. Lists that rebuild should also skip rebuilding while one of their inputs has focus (see `drawPL`).
- Editing pattern: Python `rep(old, new)` with `assert count == 1`, then `python3 tools/build.py && node tools/smoke.js`, then commit and push. The remote may print "repository moved": that is harmless.
- Auto-update: `tools/build.py` puts a short hash of the page into `/*BUILD*/` and `docs/version.json`; the page checks it on load and when it becomes visible, and reloads once via `?v=<hash>` when they differ (Pages caches ~10 min).
- Commit message trailer: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Durian orchard book (`/durian/`)
- Thai per-tree record book for Mon's durian/mangosteen orchard at https://valuegraber.github.io/durian/. Self-contained `docs/durian/index.html` (same body as Mon's Claude artifact "สมุดสวนทุเรียน", ported to Firebase); no build step, edit it directly. Config in `docs/durian/firebase-config.js` (same `valuegrab` Firebase project).
- Sign-in: Firebase Anonymous auth + "ชื่อสวน + รหัสสวน". Garden id = SHA-256 of `lower(trim(name)) + '|' + code`; data at `gardens/{gid}` and subcollections trees, works, flowers, sales, money, stock, chems, recipes, meta, photos (photos are JPEG data URLs ≤230 KB). Session in localStorage `durian-session-v1`; local-only mode uses `durian-book-v1`.
- Home top: `todayHTML` tiles (stage/tasks/weather/pest), `pestCardHTML`, `gapsHTML` (dismiss in localStorage durian-gaps-off). Pest model `PESTS` (month base Jan..Dec, eastern) × orchard stage × weather in `pestRisk`; plan tab `pest` = `vPest`. Mix banner `mixBannerHTML` (localStorage durian-mixbanner-v1).
- River/flood tab `rv` = `vRiver`: Open-Meteo Flood API (GloFAS) `fetchRv` (forecast past60+30d ensemble stats; history 1995→today reduced by `rvStats` to q2/q5/p90/yearly peaks + last 1500 days), cache localStorage `durian-rv-v1`; `rvAnalyze` levels `RL` 0–3, calibrated by meta/plan.floodDate (danger=0.9×Q on that date, `rvAround`); optional river point meta/plan.rlat/rlon. Home row in `homePlanHTML`, gap 'fld'.
- Guide tab crop toggle `ui.guideCrop` (act gcrop): durian `GUIDE_HTML` vs mangosteen `MG_GUIDE_HTML` (old-tree calendar, eastern region).
- Mangosteen split: `CROPS`, ledger rows carry `crop`+`mg` share (works: by picked trees `cropOfIds`; money.crop / sales.crop, default ทั้งสวน/ทุเรียน); `ledgerFor(crop)` splits shared rows by `mgShare()` (meta/plan.mgShare % or tree count). Money crop seg `ui.crop` (act mcrop), works filter `ui.wcrop`; mangosteen harvest via `bloomRounds(st,true)` + `MG_STEPS`.
- Money tab `cost` = `vCost` (per-rai via meta/plan.rai; `CAPITAL` cats excluded from operating cost; `costYear`). Harvest plan `harvestHTML`/`HV_STEPS` atop `vFlower`; PLAN_END has 2 appended steps (-21 buyer, -10 book).
- Tab `#plan` (แผนงาน/อากาศ/คู่มือ): mode pbz|nat in meta/plan.mode (PLAN_A vs PLAN_A_NAT; guide sections data-m="pbz|nat"); spray/fertilizer calendar from `PLAN_A` (offsets from post-harvest date H) and `PLAN_B`/`PLAN_END` (offsets from bloom rounds in flowers, or expected bloom B). State in `meta/plan` {lat,lon,canopy,H,B,done}. Weather from Open-Meteo (forecast + past_days=30, plus 3-model rain spread), cached in localStorage `durian-wx-v1`; `wxAnalyze` makes spray windows, stage alerts, water need. Guide text is `GUIDE_HTML`.
- Needs Anonymous enabled in Firebase Auth and this rule:
  `match /gardens/{gid} { allow get, create, update: if request.auth != null; allow list, delete: if false; match /{coll}/{doc} { allow read, write: if request.auth != null; } }`
